# AGENTS.md

Academic C++20 project (TFG): search algorithms for the Referee Assignment Problem (RAP).
Goal: maximize retribution per hour worked by reducing travel and idle ("tiempos muertos") time.
The domain model, the JSON input and reports (`io/json.hpp`, `io/instancia_json.hpp`, `io/informe.hpp`), the packed search state (`algorithms/estado.hpp`), the state arena (`algorithms/arena.hpp`), the state transitions (`algorithms/transiciones.hpp`), the objective function (`algorithms/objetivo.hpp`), the static-data construction (`algorithms/tiempo.hpp`, `algorithms/instancia_dia.hpp`, `algorithms/construir_instancia.hpp`, `algorithms/proveedor_distancias.hpp`), the orchestration and per-referee metrics (`algorithms/orquestacion.hpp`, `algorithms/metricas.hpp`), the CLI (`src/main.cpp`), the Python launcher (`scripts/ejecutar.py`), the OSRM client (`io/osrm.hpp`) and their tests are the real code so far.

## Architecture

- Public headers in `include/referee_scheduler/{domain,algorithms,io}/`; implementations in matching `src/`; entrypoint `src/main.cpp`.
- `referee_scheduler_domain` is an `INTERFACE` (header-only) CMake target. Domain entities have no `.cpp`; do not add one.
- `referee_scheduler_algorithms` is a **`STATIC` target** (it stopped being `INTERFACE` when the static-data construction landed). It compiles `src/algorithms/*.cpp` (including `orquestacion.cpp` and `metricas.cpp`) and links `referee_scheduler_domain` PUBLIC. Header declarations stay in `include/`; logic goes in `src/`. Link it from anything that includes `algorithms/`. The transition template `generar_hijos(..., consumidor)` is header-only because it must inline the callback; its vector overload lives in `transiciones.cpp`.
- `referee_scheduler_io` is a **`STATIC` target** that always exists: it compiles the JSON parser, the instance loader and the reports (`src/io/json.cpp`, `src/io/instancia_json.cpp`, `src/io/informe.cpp`), links `referee_scheduler_algorithms` PUBLIC. If `find_package(CURL)` succeeds it also compiles `src/io/osrm.cpp`, links `CURL::libcurl` PRIVATE and defines `REFEREE_SCHEDULER_CON_CURL` PUBLIC for `main.cpp`. `algorithms/` never depends on `io/`: the dependency is inverted through `algorithms::ProveedorDistancias`, and the client implements it.
- `scripts/ejecutar.py` is the user entrypoint: it builds with CMake if available (otherwise `g++`), runs the binary from the repository root and by default writes the JSON report to `data/generated/resultado_<input>.json`.
- `examples/osrm_smoke.cpp` is a manual network check (`referee_scheduler_osrm_smoke`), not a CTest test.
- All domain types are in `namespace referee_scheduler::domain`. Includes use the `referee_scheduler/domain/x.hpp` prefix (`-Iinclude` adds the root).
- Search/algorithm types live in `namespace referee_scheduler::algorithms` (`include/referee_scheduler/algorithms/`). They must not depend on `domain::Estado`.

## Conventions (differ from C++ defaults)

- Domain entities are `class` with **public fields**, no getters/setters, and default member initializers (`int id = 0;`). The JSON loader fills them; do not reintroduce encapsulation/accessors unless asked.
- Spanish naming throughout: types `Equipo, Sede, Arbitro, Partido, Plaza, Asignacion, Estado`; fields like `sede_id`, `plaza_id`, `equipo_local_id`.
- Cross-entity references use `int` ids, not nested objects or pointers.
- A `Partido` requires one or more `Plaza` (one per role in `enum class Rol`). `nivel_requerido` and `retribucion` live on `Plaza`, not `Partido`. `Asignacion` is the pair (`plaza_id`, `arbitro_id`).
- `Arbitro` declares `disponibilidad_inicio`/`disponibilidad_fin` (no separate max-hours cap) and `domicilio_id`, the id of his **real home location**. Referee location/time is derived from the last assigned match's `sede_id`/`final`.

## Search state (decided)

- The search state is `algorithms::Estado` in `include/referee_scheduler/algorithms/estado.hpp`: `std::array<EstadoArbitro, kMaxArbitros>`, 2400 B, trivially copyable, no allocations. It is 4 B per referee, so 16 referees fit in a 64 B cache line and the full state spans 38 lines. `Estado` is the **maximum-capacity view** (initial state, debug, tests); the search nodes are stored by `algorithms::Arena`.
- `EstadoArbitro` is exactly 4 B: `sede_id : 10`, `minuto_liberacion : 11`, `reservado : 11` (10 + 11 + 11 = 32). `static_assert` enforces `sizeof(EstadoArbitro) == 4`, `sizeof(Estado) == 2400` and trivial copyability. The bitfield layout is implementation-defined; the size assertion is the guarantee. Do not add fields without redoing the bit budget.
- The state is the **minimal sufficient statistic** of the past: where each referee is, when he becomes free, plus 11 reserved bits. It stores no history (teams already refereed, match counts, etc.). Any per-referee rule needing history does not fit in 32 bits.
- `minuto_liberacion` is an absolute minute from the day's `t0`. A day is 1440 min, so 11 bits (2047) suffice with margin.
- `sede_id` has no sentinel: the initial state sets each referee at his **domicile** (`Arbitro::domicilio_id`) and free from `disponibilidad_inicio`. Match sedes and referee domiciles are **disjoint location sets**, and no assignment ever moves a referee to his domicile, so `sede_id == domicilio` identifies the initial state exactly. That is what lets `coste_asignar` treat the first trip differently without storing any history. Phase 3 asserts the disjunction.
- `reservado` is unused by design. There is **no per-referee retribution cap**; the field is a bit budget for a future constraint and can be subdivided without changing `sizeof`.
- `kMaxArbitros = 600` is a compile-time **capacity**, not a count. The real count `n_arbitros` is runtime data (in the instance). Only `[0, n_arbitros)` is meaningful. Never loop to `kMaxArbitros`. Assert `n_arbitros <= kMaxArbitros` on load: unused slots are zero, and a zero slot looks like a valid referee (sede 0, minute 0).
- Execution is **per day**: Friday, Saturday and Sunday are independent and run in parallel. Each day builds its own instance and state. Per-day **referee compaction** is the agreed direction: `Estado` indexes the day's available referees `0..N_dia-1`, not global ids. Optional per-day **sede compaction** only frees bits (10 -> 6/7), not bytes.
- `domain::Estado` (`vector<Asignacion>` + `ultima_sede_arbitro` + `franja_ocupada_arbitro`) is **legacy and superseded** by `algorithms::Estado`. Do not extend it. Its fate (delete, or keep as the solution type) is undecided; ask before changing it. The `franja` concept is superseded by continuous minutes.

## Arena (decided, v1 implemented)

- `algorithms::Arena` (`include/referee_scheduler/algorithms/arena.hpp`) stores search nodes with **stable addresses**. It receives `n_arbitros` at construction; it does not depend on the loader or the future `Instancia`.
- Each node is a contiguous block of `24 + 4·n_arbitros` bytes: a 24 B `CabeceraNodo` followed by `n_arbitros` `EstadoArbitro`. The stride is `calcular_tam_bloque(n)`, rounded up to 8 B. So a node costs 504 B at n=120 and 2424 B at n=600, not the 2400+24 of the worst case.
- `CabeceraNodo` is exactly 24 B and cannot change size without changing the address formula: `coste_g` (int64, objective step 2), `padre`, `nivel`, `flags`, `decision`. `kSinNodo` marks the root's parent.
- `decision` stores how the node was reached: `0..N-1` is the compact referee assigned to `plazas[nivel-1]`, `kDecisionVacia = 0xFFFFFFFF` means the plaza was left empty, and `kSinDecision = 0xFFFFFFFE` is the root. `decision_es_asignacion`, `decision_es_vacia` and `decision_es_raiz` are the predicates. The field is what makes reconstruction possible without diffing parent/child states.
- `flags` is the frontier's field. `kFlagAbierto` (`1u << 0`), `kFlagCerrado` (`1u << 1`) and `kFlagSuperado` (`1u << 2`) are the reserved bits. The generator writes `flags = 0`; `buscar_dijkstra` sets `kFlagCerrado` when it expands a node and `TablaEstados` sets `kFlagSuperado` on the node that stops being the canonical representative of its state (so a stale open-list entry is discarded with one bit, no hash and no extra memory access).
- `estado(nodo)` returns `std::span` of length `n_arbitros()`: it is structurally impossible to iterate the padding slots. `crear(Estado, ...)` copies only `[0, n_arbitros)` and ignores the tail.
- Nodes live in heap blocks of 64 KiB, held by `unique_ptr`; blocks never move, the block pointer vector may. Growth doubles the block count (amortized O(1)); moving the `Arena` keeps node pointers valid. Not copyable.
- Node indices are `std::uint32_t` and are permanent. `crear` asserts `n_arbitros <= kMaxArbitros`; address is `nodo / nodos_por_bloque` (current v1).
- Tests: `tests/test_arena.cpp` covers stride formula, n ∈ {1, 5, 300, 600}, copying only the prefix, span length, pointer stability across ~20 blocks and memory counters.
- Studied micro-optimizations (zeroing, division, hugepages/TLB) are **not implemented**: see `docs/optimizaciones.md`. They will be explored once Dijkstra works and can be measured.

## Transitions (step 3 implemented)

`include/referee_scheduler/algorithms/transiciones.hpp` + `src/algorithms/transiciones.cpp` implement the first search step: build the initial state, create the root and generate children. The bit-level write per assignment is exactly 4 B (`sede_id`, `minuto_liberacion`, `reservado`).

- `estado_inicial(dia)` returns the maximum-capacity `Estado` with, for each compact referee `i`: `sede_id = arbitros[i].domicilio`, `minuto_liberacion = arbitros[i].primer_inicio`, `reservado = 0`. The tail `[n_arbitros, kMaxArbitros)` stays zero. At home is the only state where `sede_id == domicilio`; that is what selects the first-trip regime in `coste_asignar`.
- `crear_raiz(arena, dia)` requires a fresh arena (`nodos_creados() == 0`) of the same `n_arbitros`, builds the initial state and creates node 0 with `coste_g = 0`, `padre = kSinNodo`, `nivel = 0`, `flags = 0`, `decision = kSinDecision`. It asserts `n_arbitros > 0`: days without referees are resolved by the orchestrator before creating an `Arena`.
- `es_meta(arena, dia, nodo)` is `cabecera(nodo).nivel == dia.n_plazas()`. The level is the number of plazas already decided and the index of the next plaza, so the leaf cost `g` already includes all travel, waits, telescoped returns and empty secondary plazas; no terminal cost is added.
- `generar_hijos(...)` has two public forms:
  - `generar_hijos(arena, dia, nodo, parametros, std::vector<uint32_t>& hijos)` clears and fills the vector (implemented in `.cpp`);
  - `generar_hijos(arena, dia, nodo, parametros, consumidor)` is a header-only template that invokes the callback directly and avoids the intermediate vector. Both share `detalle::generar_hijos_impl`, so there is only one copy of the cost logic.
- Child order is deterministic: candidates in ascending compact-id order and then the empty-plaza branch. For each candidate, the generator reads its 4 B from the parent state, gets `d(sede_actual, sede_plaza)`, `d(sede_plaza, domicilio)` and `d(sede_actual, domicilio)`, calls `coste_asignar`, creates the child by copying the parent state and patches only that referee with `(sede_plaza, minuto_fin)`. The empty branch copies the parent state unchanged and charges `coste_dejar_vacia`; a principal plaza has no empty branch.
- The generator rejects any transition with a `kMinutosInalcanzable` cell (`viaje`, `retorno_nuevo` or `retorno_anterior`), even though phase 5 already filters the home↔venue round trip. This keeps the telescoped return finite and preserves the `>= epsilon` edge guarantee required by Dijkstra.
- `tiene_solucion_estatica(dia)` is a cheap **necessary** check: every principal plaza must have at least one static candidate. It does not detect dynamic lateness. Days with no referees and only secondary plazas are valid (leave all empty); a principal without candidates is infeasible.
- `reconstruir_solucion(arena, dia, meta)` walks `padre` from the goal to the root and reads `decision`: a node with `nivel = p + 1` stores the decision for `plazas[p]`. It returns `SolucionDia{coste = cabecera(meta).coste_g, decisiones}` with global `plaza_id`, `partido_id` and `arbitro_global` (`-1` for an empty plaza), in chronological order.
- Tests: `tests/test_transiciones.cpp` covers the initial state, root, first trip from home, empty secondary plaza, principal without candidates, late arrival, the static feasibility check, the unreachable-return sentinel, the callback/vector equivalence and full reconstruction with exact cents (982 in the two-match fixture).

## Frontier and Dijkstra (step 4 implemented)

Three pieces, each in its own header, plus the engine in a `.cpp`. The design follows `bucket_t`/`closed_t` from [ksearch](https://github.com/clinaresl/ksearch) (open list as buckets of integer keys, closed list consulted to avoid revisiting), adapted to our cost model.

- `ListaAbierta` (`algorithms/abierta.hpp`, header-only, like `Arena`): open list as a `std::vector<std::vector<uint32_t>>` of buckets indexed by `clave − base`. Keys are **int64 cents**, not `int`; what travels is the 4 B node id, and the key lives in `CabeceraNodo::coste_g`. `base` is fixed by the first insertion and aligned down to `anchura`; `primero_` is a cursor that only advances, so `insertar` and `extraer_min` are amortized O(1) with no comparator. LIFO inside a bucket (`push_back`/`pop_back`). Buckets never shrink and keep their capacity. Not copyable, movable. Chosen over a heap because the keys are non-negative integers and, above all, never decrease; a `std::priority_queue` survives only as the oracle in `test_abierta.cpp`.
- **The insertion precondition is not "non-decreasing keys"** but "no key may fall in an already-consumed bucket". After an extraction the cursor can skip empty buckets and report a bound *higher* than the parent's key, so `insertar` asserts against `cota_actual()` (the aligned base of the cursor's bucket), not against `clave_min()`. Dijkstra guarantees it: a child costs at least as much as its parent, and the parent left that bucket.
- `anchura` (default `1` = one bucket per cent) is an escape hatch for days whose key range explodes (each empty secondary plaza adds its retribution). With `anchura > 1` `clave_min()` returns the bucket's lower bound, extraction is no longer exact and the stop rule must drain the current bucket; optimality is preserved, only more nodes are explored.
- `TablaEstados` (`algorithms/tabla_estados.hpp`): the closed list, as an open-addressing table (linear probing, power-of-two capacity, load factor 0.5) of 16 B entries `{huella, nodo}`. It stores the node id, not a copy of the state (a copy would be 504 B at n=120, twice, as ksearch does). Key = **(nivel, estado)**: the level is mandatory because two empty plazas leave the same physical state at different levels and those nodes are not comparable. `huella_estado` is FNV-1a over the 4-byte words plus the level, finished with splitmix64 (the table masks low bits); the hash only selects the slot, equality is always decided by `nivel` + `memcmp` of `4·n` bytes, so a collision can never prune a valid solution. Rehash uses the stored hash only (no arena reads).
- `mejorar(arena, nodo)` replaces the representative only when `coste_g` is **strictly** smaller and marks the old node with `kFlagSuperado`; on a tie or worse it returns `false` and the first node to arrive keeps the state (reproducible search).
- **Duplicate detection happens at generation time**, in the consumer passed to `generar_hijos`: a rejected child never enters the open list and its whole subtree is never explored. The node is still created in the arena (the generator does not query the table, to keep its hot loop clean), which is the cheap part compared with the pruned subtree. This matters because duplicates are the norm here: with a time-only objective, assigning a referee the principal or the assistant of the same match at the same venue and time produces the same state **and** the same cost.
- `buscar_dijkstra` (`algorithms/busqueda.hpp` + `src/algorithms/busqueda.cpp`): builds the root, then loops with the budget check, the stop rule `clave_min() >= incumbente`, the O(1) discard of `kFlagSuperado` entries, `kFlagCerrado` on expansion, the `g >= incumbente` cut and the table check. It returns `ResultadoBusqueda` with the cause (`Optima` / `SinSolucion` / `PresupuestoAgotado`), the reconstructed `SolucionDia`, the goal node and metrics (created, expanded, discarded, stale extractions, distinct states, peak open list, arena/open/table bytes, milliseconds).
- **No reopening**: non-decreasing extraction plus "replace only if strictly better" means a state that has already been extracted keeps its cost, so `kFlagCerrado` is asserted as a debug invariant (with `anchura == 1`; a wider bucket can reopen, and the loop supports it).
- `OpcionesBusqueda { max_nodos = 1'000'000, anchura_cubo = 1 }`: the node budget is a safety net against combinatorial explosions, not a parameter; when it is hit, the solution found (if any) is **not proven optimal**. The check runs once per expansion, so the last expansion may overshoot slightly.
- A day with `n_plazas == 0` is handled naturally: the root is the goal, cost 0. A principal without candidates ends as `SinSolucion` (the orchestrator can short-circuit it with `tiene_solucion_estatica`). A day without referees never reaches this code (`Arena` requires `n_arbitros > 0`).
- Tests: `test_abierta.cpp` (order, LIFO ties, base far from zero, width > 1, move, property test against `std::priority_queue` with 20 000 operations), `test_tabla_estados.cpp` (new/repeated state, same state at different levels, replacement only with a lower cost, superseded marking, significant reserved bits, 200 states through rehash and collisions, `reservar`, hash) and `test_busqueda.cpp` (982 fixture, cheaper empty secondary plaza, principal without candidates, node budget, day without plazas, and the duplicate fixture validated against an exhaustive DFS oracle, including `anchura_cubo = 100` giving the same optimum).

## Objective function (decided, implemented)

- `coste_asignar` and `coste_dejar_vacia` live in `include/referee_scheduler/algorithms/objetivo.hpp`: header-only, no allocations. They depend on `EstadoArbitro` and `domain::Rol`, never on `domain::Estado`. Lower cost is better (minimization).
- Everything is counted in **integer cents** (`std::int64_t`); `a_centimos(double)` rounds euros to cents once. `kCentimosPorMinuto = 14` (8,4 €/h) and `kEpsilonCentimos = 1`; `ParametrosObjetivo` lets tests and future experiments override both.
- Assignment cost has **two regimes**, distinguished by `EstadoArbitro::sede_id == domicilio` (only the initial state is at the domicile):
  - **At home (first trip of the day)**: `minuto_liberacion` holds `primer_inicio`, the earliest minute he can **referee** (not the departure time). He may leave home earlier, so the transition is feasible iff `minuto_inicio_plaza >= minuto_liberacion`, regardless of travel time. He departs at `inicio − viaje`, so there is no wait: `ε + tiempo_viaje · k + (retorno_nuevo − 0) · k`. The trip is still charged as consumed time.
  - **Already worked**: `llegada = minuto_liberacion + tiempo_viaje`; infeasible if `llegada > minuto_inicio_plaza`. Cost `ε + (tiempo_viaje + espera) · k + (retorno_nuevo − retorno_anterior) · k`, with `espera = inicio − llegada` charged in full (he is no longer at home).
  - The return adjustment is prospective and telescopes, so a chain of assignments pays one real return trip at the end and every edge stays `>= ε` with a metric matrix (Dijkstra-safe).
- An infeasible transition returns `nullopt` (the generator must not create that child): starting before availability in the first regime, arriving late in the second. Negative waits never cheapen a route.
- Covered plazas do **not** add their retribution: the objective charges only time. Leaving a plaza empty with `Rol::Principal` is forbidden (`nullopt`); any secondary role costs its full retribution in cents (no epsilon).
- Future idea, **not implemented**: when the gap allows `ida + vuelta + 1 h en casa`, evaluate the same assignment "via home" (`sede = domicilio`, `liberacion += d(actual, domicilio)`) and keep the cheaper of the direct and via-home costs, so long gaps are charged as travel instead of dead time. Detailed in `docs/mejoras-practicas.md`; it needs the travel matrix and the transition generator.
- Tests: `tests/test_objetivo.cpp` covers cents conversion, the first trip from the domicile (leaving before availability), en-route wait, positive/negative return adjustment, late arrival, custom k/ε and empty plazas.

## Static data (decided; phases 1–5 and JSON input implemented)

The design is five sequential phases that prepare the structures for the search. Phases 1–5 are implemented in memory and step 5g (the JSON loader) is implemented on top of them.

- **Input aggregate**: `domain::Instancia` (`domain/instancia.hpp`) holds `equipos`, `sedes`, `arbitros`, `partidos`, `plazas`. Header-only, public fields, references by global `int` id.
- **`Sede` has `latitud`/`longitud`** (WGS84, degrees). Travel times come from the **OSRM** `/table` API, not from a matrix stored in the instance. Both coordinates 0 means "no real coordinates". A `Sede` is a **location**: either a match venue or a referee's home (`Arbitro::domicilio_id`), never both. The loader creates a separate row for a home even if it sits at the same coordinates as a venue; the two id sets are disjoint and phase 3 asserts it.
- **Time utilities** (`algorithms/tiempo.hpp` + `src/algorithms/tiempo.cpp`): `DiaCivil`, `dia_de(time_t)` (local time via `localtime_r`), `minuto_del_dia`, `indice_dia` (Howard Hinnant civil-days, no `time_t/86400`), `minuto_absoluto` (`indice_dia*1440 + minuto`) and `minuto_en_dia` (clamped to `[0, 1440]`). This is the only timezone-dependent code. `kMinutosPorDia = 1440`. **`t0` is 00:00 of the day**, so minutes are `hour*60 + minute` and a night match may exceed 1440 but stays below 2048.
- **Phase 1, partition by day** (`GrupoDia`, `agrupar_por_dia`): groups `partidos` by the **civil date of `inicio`** (never `final`), returns days sorted and, inside a day, positions in input order. A Friday 23:30 match ending Saturday 01:00 belongs to Friday. Indices are `std::size_t` positions in `Instancia::partidos`, no copies.
- **Phase 2, referee compaction** (`ArbitroDia`, `compactar_arbitros`): a referee belongs to the day if his availability window (in **absolute minutes**) contains a valid **start** minute of that day (`[dia*1440, dia*1440+1439]`). Comparing already-clamped minutes would wrongly include a referee available only the previous day. `primer_inicio` is the window start clamped to `[0, 1439]` (guaranteed by the include filter) and `ultimo_inicio` the window end clamped to `[0, 1440]`, where **1440 means no limit**. Result sorted by `id_global`, so the compacted id (vector index) is deterministic; the index is `0..N_dia-1`. `equipos_vetados` keeps only teams playing that day, sorted and deduplicated (binary search later).
- **Availability semantics (user-decided)**: the declared end is a bound on the **match start**, not on the match end. Available until 23:00 ⇒ a match starting at 23:00 is allowed even if it ends after midnight. The declared start (`primer_inicio`) is the earliest minute he can **referee**, not the earliest departure: available from 9:00 he can serve a 9:00 match even if the trip takes two hours, because he leaves home at 7:00. The first trip is still charged as travel time.
- **Phase 3, distance matrix — implemented**: `algorithms::ProveedorDistancias` (`algorithms/proveedor_distancias.hpp`) defines `Coordenada`, `Minutos = uint16_t`, `kMinutosInalcanzable = 65534` and `kMinutosViajeMinimo = 1`. `construir_matriz_distancias` compacts the day's locations (**match sedes ∪ referee domiciles**) to `0..M-1` sorted by global id, asserts `M <= 1024` (10-bit `sede_id`) and asserts that the two sets are **disjoint** (a match never plays at a domicile), asks the provider for the **full matrix**, forces the diagonal to 0, raises every other 0 to `kMinutosViajeMinimo` (OSRM returns 0 between very close points; no displacement is free) and optionally applies `cerrar_metricamente` (Floyd–Warshall, `uint32` sums, unreachable cells never used as bridges). It also fills `ArbitroDia::domicilio` with the compact index. `construir_instancia_dia` (phases 1–5) and `construir_instancias` exist. `OpcionesDistancias { bool cerrar_metricamente = true; }`.
  - The OSRM client is `io/osrm.hpp` + `src/io/osrm.cpp`: `build_url` uses `lon,lat` with 6 decimals; the server limit is on **table dimensions** (verified: 100 rows × 100 cols with 200 coordinates in the URL returns 200), so it batches 100 sources × 100 destinations, keeps all coordinates in the URL, omits `sources`/`destinations` for the full matrix, parses `durations` with a minimal JSON scanner (`null` → unreachable, `ceil(sec/60)`), and caches with an **FNV-1a** key in `data/generated/distancias_<hash>.txt` (gitignored). Network/HTTP errors throw `std::runtime_error`; the constructor clamps `maximo_por_peticion` to ≥ 1.
  - Tests: `test_instancia.cpp` (fake providers, asymmetric matrix, closure, unreachable, minimum 1-minute trip, compacted domiciles, 3-day pipeline) and `test_osrm.cpp` (offline: conversion, JSON parsing, URL).
- **Phase 4, chronological plazas — implemented**: `construir_plazas(instancia, grupo, sede_global)` expands the day's matches into `PlazaDia` records sorted by `(minuto_inicio, sede, partido_id, plaza_id)`; the index in `InstanciaDia::plazas` **is the tree level**. `PlazaDia` (48 B, trivially copyable) carries `minuto_inicio`, `minuto_fin`, the compact `sede` (`uint16_t`), `nivel_requerido`, `retribucion_centimos` (`a_centimos`, converted once), `rol`, `partido_id`, `plaza_id` and both team ids; `es_principal()` is the `rol == Rol::Principal` test, so the role is stored instead of a duplicated bool. Decisions closed here: (a) the tie-break is `(minuto_inicio, compact sede, partido_id, plaza_id)` — total and deterministic, and the compact sede orders like the global id; (b) `minuto_fin` is the **end of the match**, measured in absolute minutes from the day's 00:00, so a Friday 23:30→01:00 match ends at **1500** (`minuto_en_dia` would clamp it to 1440) and it is exactly the referee's release minute. Per-match data (minutes, compact sede) is computed once, not once per plaza; plazas whose match is not in the day are skipped. `InstanciaDia` exposes `plazas` and `n_plazas()`; `construir_instancia_dia` chains phases 1–5.
- **Phase 5, per-plaza candidate lists — implemented**: `construir_candidatos(const InstanciaDia &)` returns `ListasCandidatos{offsets, candidatos}`, a flat CSR that `construir_instancia_dia` moves into `InstanciaDia::offset_candidatos` (`n_plazas()+1` boundaries) and `InstanciaDia::candidatos`. One `plaza × árbitro` pass with four static filters, cheapest first: `nivel >= nivel_requerido`; `primer_inicio <= minuto_inicio <= ultimo_inicio` (**no** travel added to `primer_inicio`: the first trip may start before availability, and this is exactly `coste_asignar`'s at-home feasibility test); neither match team in `equipos_vetados` (sorted, `std::binary_search`); and **reachability in both directions** `d(domicilio, sede) != kMinutosInalcanzable` **and** `d(sede, domicilio) != kMinutosInalcanzable` (a route must exist both ways: the objective uses the return leg for the telescoped adjustment, so a `65534` there would produce false or negative costs). Values are **compacted** referee ids (`0..n_arbitros-1`), ascending inside each plaza (deterministic tie-break), so a `uint32_t` is enough. Accessors: `n_candidatos(p)`, `candidatos_de(p)` (returns `std::span<const uint32_t>`, so the tail of the next plaza is unreachable) and `n_candidatos_totales()` (no duplicated field). A plaza with no candidates keeps both boundaries equal; a day without referees gives `{0, 0}` per plaza. The list is **necessary, not sufficient**: whether the referee arrives in time depends on the state and is decided by the child generator.
- Tests: `tests/test_instancia.cpp` covers phases 1–5 (and the time utilities); it must grow one block per phase.

### JSON input, orchestration and reports (step 5g implemented)

- **Parser**: `io/json.hpp` + `src/io/json.cpp` implement a minimal DOM parser (objects, arrays, strings with `\uXXXX`/UTF-8, numbers, booleans, null). Duplicate object keys are an error, nesting is capped and syntax errors report line/column. `io/roles.hpp` maps the role names (`principal`, `asistente`, `anotador`, `juez_linea`).
- **Loader**: `io/instancia_json.hpp` + `src/io/instancia_json.cpp` read a JSON file into `domain::Instancia`. The five collections (`equipos`, `sedes`, `arbitros`, `partidos`, `plazas`) are mandatory. Dates are ISO-8601 **local** (`YYYY-MM-DDTHH:MM[:SS]`). The loader validates unique non-negative ids, all cross-references, the venue/home disjunction, coordinates (not `(0,0)`), `final >= inicio`, availability order, one principal plaza per match, no repeated role in a match, non-negative levels/retributions, and the 11-bit `minuto_fin` limit. User-data errors are `ErrorInstancia` (never `assert`); syntax errors are `ErrorJson`.
- **Orchestration**: `algorithms/orquestacion.hpp` + `src/algorithms/orquestacion.cpp` expose `resolver_instancia`. It builds each day with phases 1–5, resolves trivial days without an arena (no plazas; no referees and only secondary plazas), short-circuits days with a principal without candidates (`SinSolucion`), checks the per-day `kMaxArbitros` capacity and runs `buscar_dijkstra` otherwise. It aggregates costs, nodes, times and per-referee metrics.
- **Per-referee metrics**: `algorithms/metricas.hpp` + `src/algorithms/metricas.cpp` replay each referee's route from the reconstructed decisions: first trip from home (`salida = inicio - viaje`), later trips with wait, return home at the end, total dedicated minutes and effective €/h. `coste_tiempo_centimos = coste - retribucion_perdida`.
- **Reports**: `io/informe.hpp` + `src/io/informe.cpp` write the terminal summary (cost, node/budget metrics, times, travel/wait/match minutes, effective rate) and the optional full JSON (all assignments, per-day and global referee metrics). The terminal deliberately omits assignments and the referee table.
- **CLI**: `src/main.cpp` requires only the instance path; `--salida`, `--max-nodos`, `--anchura-cubo`, `--osrm-url`, `--cache-dir` and `--sin-cache` are optional. It uses `io::OsrmDistancias` when built with libcurl, otherwise it reports that no provider is available. Exit codes: `0` run completed with a solution, `2` some day without solution, `1` input/IO/network error.
- **Python launcher**: `scripts/ejecutar.py` builds if needed (CMake or `g++`), runs from the repository root and writes `data/generated/resultado_<input>.json` by default (`--sin-json` disables it).
- **Examples**: `data/instances/` holds the base `ejemplo.json` plus varied instances (minimum, small, many referees, many plazas, both, multi-day, vetoes/levels, overnight, infeasible and dispersed homes). Large examples may hit `OpcionesBusqueda::max_nodos`; that is expected without a heuristic.
- **Tests**: `test_json.cpp` (parser/loader/errors), `test_informe.cpp` (text + JSON roundtrip), `test_metricas.cpp` (route reconstruction), `test_orquestacion.cpp` (trivial days, multi-day aggregation and JSON integration).

## Roadmap / scope

Agreed order:

1. **Arena** for state storage: stable block storage; block size `24 + 4·n_arbitros` computed at run time; the arena receives `n_arbitros`, it does not depend on the loader. **v1 implemented** (`algorithms/arena.hpp`); v2 micro-optimizations deferred to `docs/optimizaciones.md`.
2. **Objective function**: additive and positive, in integer cents; `ε + tiempo · k` with k = 14 c/min, return-trip adjustment, and empty secondary plazas charged their lost retribution. **Implemented** (`algorithms/objetivo.hpp`); the travel lookup is filled in step 5.
3. **State transitions and operations**: the 4-byte write per assignment; decision fields of the node. **Implemented** (`algorithms/transiciones.hpp` + `src/algorithms/transiciones.cpp`): initial state, root, child generator (vector and callback), static feasibility and reconstruction.
4. **Search frontier / open list**. **Implemented** (`algorithms/abierta.hpp` + `algorithms/tabla_estados.hpp`): bucket open list keyed by integer cents, open-addressing closed list keyed by `(nivel, estado)`, duplicate detection at generation time and `kFlagSuperado` for stale entries.
5. **Static data**:
   a. In-memory instance (`n_arbitros`, `t0`, referees, matches, plazas). **Implemented**: `domain::Instancia`, `domain::Sede` coordinates.
   b. Per-day referee compaction (global id -> `0..N_dia-1`) and sede remap. **Implemented**: `compactar_arbitros` and `construir_matriz_distancias`.
   c. Travel-time matrix. **Implemented**: OSRM `/table` via `io::OsrmDistancias`, with cache.
   d. Minute offsets for match start/end. **Implemented**: `tiempo.hpp` with `t0 = 00:00`.
   e. Chronological ordering of plazas. **Implemented**: `construir_plazas` / `PlazaDia` (phase 4).
   f. Per-plaza candidate lists (CSR + reachability). **Implemented**: `construir_candidatos` / `ListasCandidatos` (phase 5).
   g. Instance loader / file format (`data/instances/`). **Implemented** (step 5g): `io/json`, `io/instancia_json`, `io/roles`, `algorithms/orquestacion`, `algorithms/metricas`, `io/informe`, CLI and Python launcher.
6. **Assemble Dijkstra / A\***. **Dijkstra implemented** (`buscar_dijkstra`): the minimal loop over the frontier, with node budget, incumbent stop rule and metrics. A\* (admissible/consistent heuristic, greedy initial incumbent) is the next step; without a heuristic a day of 18 plazas and 20 referees already exhausts a 300 000-node budget.
7. **Final validation**: recompute constraints and cost from the reconstructed assignments.

## Known gaps / pending decisions

- Phase 4 is closed: the plaza order is `(minuto_inicio, compact sede, partido_id, plaza_id)` and `PlazaDia::minuto_fin` is the match end in absolute minutes of the day (can exceed 1440). It is exactly the referee's release minute, so the transition generator must write it into `EstadoArbitro::minuto_liberacion`. The JSON loader validates referential integrity before phase 4; `construir_plazas` still skips plazas of other days as a defensive behaviour.
- Phase 5 is closed: candidate ids are **compacted** referee ids (`uint32_t`, ascending per plaza) and the static filters deliberately exclude travel time (only route existence, now in both directions home↔venue). The phase-2 inclusion filter is a **superset** (a referee whose window touches the day but no real match start can end up with empty lists); that is intentional and costs only state bytes. A plaza with an empty list can only be left empty: the child generator must not invent candidates, and `coste_asignar` still enforces feasibility and the principal-plaza rule. A principal plaza with an empty list makes the day infeasible; `tiene_solucion_estatica` detects it before creating the arena.
- `InstanciaDia` does **not** record whether the distance matrix was closed metrically. Dijkstra/A\* require `OpcionesDistancias::cerrar_metricamente = true` (the default); without it, the telescoped return adjustment can make an edge negative. Storing a `bool metrica` in `InstanciaDia` is a possible future guard.
- Zero-referee and zero-plaza days are resolved by the orchestrator, not by `Arena`: `Arena` asserts `n_arbitros > 0`. A day without referees and only secondary plazas has the trivial solution "all empty"; a principal without candidates is infeasible. `Arena` is only created for `n_arbitros > 0` and `n_plazas > 0` days that pass `tiene_solucion_estatica`.
- The JSON input is strict: the five collections are mandatory, each match needs exactly one principal plaza, every reference must exist, and dates are local ISO-8601 (no timezone offset). The format carries no distance matrix; real runs need OSRM (or an injected provider in tests). The loader rejects `minuto_fin >= 2048` before the phase-4 `assert`.
- `data/instances/` contains varied examples. Large instances (many referees/plazas) can exhaust `OpcionesBusqueda::max_nodos` and finish as `PresupuestoAgotado`; this is expected until A\* or a greedy incumbent lands.
- The public OSRM demo server is for demos and has limits/rate limits. `OpcionesOsrm::url` is configurable for a local Docker instance; do not hardcode the demo URL anywhere else. The cache key includes URL + profile + coordinates.
- `Sede` coordinates are required: a sede with both at 0 triggers an `assert` in `construir_matriz_distancias`.
- `Arbitro::disponibilidad_*` are `time_t`; the conversion is done in `tiempo.hpp`. The declared start (`primer_inicio`) is the earliest **match start** he can serve; the first trip may leave home before it, so no per-referee departure field is stored. That regime is detected with `sede_id == domicilio`, which is only possible in the initial state because match sedes and domiciles are disjoint.
- If the "via home" idea is implemented, the referee would legitimately be at his domicile **after** having worked, so `sede_id == domicilio` would no longer identify the initial state. That change needs a marker (a reserved bit or equivalent) before it can land.
- `kMaxArbitros = 600` is a hard cap; if the real instance exceeds it, that is a bug. The 10-bit `sede_id` requires `M_dia <= 1024`, guaranteed by per-day sede compaction.
- The per-day model starts every day at home and charges a return trip at the end (the telescoped adjustment). It does **not** carry the physical location across midnight: a Friday match ending at 01:00 and a Saturday availability are two independent days. This is a deliberate simplification of the per-day execution; changing it would require sharing state between days and revisiting the `sede_id == domicilio` initial-state marker.
- Node budget / memory limit: **decided** in step 4. `OpcionesBusqueda::max_nodos` (default 1 000 000) caps the arena per day and `ResultadoBusqueda::causa` says whether the solution is proven optimal (`Optima`) or merely the best found (`PresupuestoAgotado`). Tie-breaking is settled at both ends: the generator fixes the child creation order (candidates ascending, then empty), the bucket open list pops LIFO inside a bucket and `TablaEstados` keeps the first node to reach a state on ties. The parallel mechanism for the three days is still undefined.
- The incumbent stop rule is in place but there is **no heuristic**: Dijkstra explores every node cheaper than the optimum. A synthetic day of 18 plazas, 20 referees and 26 venues already exhausts a 300 000-node budget in ~0.2 s (197 000 distinct states, 33 MB of arena), so the next improvement is A\* with an admissible lower bound (plus a greedy initial incumbent), not micro-optimization. `docs/optimizaciones.md` records the frontier ideas and the measured baseline.
- `ListaAbierta` materializes one 24 B bucket header per cent between the first and the current key, and keys keep growing while the search runs (empty secondary plazas add their retribution). `anchura_cubo` is the knob; a two-level bucket layout is the structural fix if it ever matters. Nothing is implemented yet.
- `TablaEstados` hashes the whole state per generated child (FNV-1a over the 4-byte words). That is the dominant per-child cost on small days; a cheaper mix or a state digest computed once when the child is created are open options.
- Tests cover smoke, arena, objective, transitions, frontier (open list, closed table, Dijkstra end to end), static-data phases 1–5, the JSON parser/loader, reports, per-referee metrics, orchestration and the OSRM client (offline); keep them in sync with new features.
- No benchmark or baseline in the repository yet; `docs/optimizaciones.md` proposes a minimal arena benchmark and now records the synthetic frontier baseline to be added once the search runs.
